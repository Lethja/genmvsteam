# genmvsteam.sh

`genmvsteam.sh` is a small Bash script that generates a move script
for transferring Steam games between Steam libraries.
It collects all the files that should move between Steam libraries 
(including Proton configurations workshop directories) 
given only the games' common folder path as the source input.

Rather than moving the files itself 
`genmvsteam.sh` generates another Bash script 
which the user can inspect or edit before execution if they choose to. 

## Usage
Using `genmvsteam.sh` is similar to the typical UNIX `mv` and `cp` commands.
It takes in one or more source directories
and treats the last directory as the destination.

```
./genmvsteam.sh SOURCE... DESTINATION
```

Running `genmvsteam.sh` does not move anything by itself.
It prints a second Bash script. Save that script, inspect it, then run it.

### Parameters
The source path(s) should point to the subfolder in `steamapps/common` of the
game you want to move. You can move one or multiple games 
from one or multiple Steam libraries at the same time.

The destination path should point to the `steamapps` directory
of the Steam library you want all the games to be moved to.

### Example

Let's say you have a Steam Deck with Half-Life 2 and Blender installed
to the internal storage, and you want to move both to a SD card to free space.
The `genmvsteam.sh` command may look something like this:
```
./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Half-Life\ 2/ ~/.local/share/Steam/steamapps/common/Blender/ /run/media/deck/sdcard/steamapps/
```
> Note: there's no need to overthink the paths you give to `genmvsteam.sh`.
> If something looks wrong with any of the paths provided to the script, then it will tell you and not continue: 
> ```
> $ ./genmvsteam.sh ~/Documents/Taxes.xlsx /run/media/deck/sdcard/steamapps/
> # Warning: source '/home/deck/Documents/Taxes.xlsx' does not look like a Steam game in a 'steamapps/common' directory.
> Error: no Steam games sources to move.
> 
> $ ./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Half-Life\ 3/ /dev/null
> Error: destination '/dev/null' does not look like a 'steamapps' directory.
> ```

Assuming there was no problem with the provided paths,
the generated script is printed to standard output,
which can be used with a UNIX pipe in several powerful ways.
See [Advanced usage with pipes](#advanced-usage-with-pipes)
for more information.

## Why does this exist?

### When Steams "Move Content" feature isn't enough

When Steams internal "Move Content" functionality works, it works well.
Unfortunately, this is not always the case, for example, 
when moving games from internal storage to a low writing speed SDcard 
on a Steam Deck or Steam Frame 
(especially large games like the 70 GB Half-Life: Alyx) 
it renders the device unusable for as long as it takes for the game to transfer, 
but you cannot leave the device alone to complete the transfer 
either as the act of SteamOS going to sleep in the middle 
of the moving game content may be interrupted when the device is turned on again.

Worse yet, if a game move is interrupted for any reason, there's a risk
the common folder will have been made on the destination and any reattempt 
to move will cause Steam to error out saying "the folder already exists",
potentially leading to the game content to be split in an unusable state 
between the two Steam libraries.

Additionally, at the time of writing, it is not possible to move multiple games
at once in the Big Picture mode like it is in the Steam desktop client.

In contrast, the scripts generated by `genmvsteam.sh` can move multiple games
from multiple different Steam libraries at once and will continue where they  
left off if the machine goes to sleep. 
If the generated script is interrupted unexpectedly (such as the device running
out of battery or panic rebooting), the script is designed in such a way 
that running it again effectively resumes the transfer.

### Advanced usage with pipes

`genmvsteam.sh` outputs the generated script to the standard output, 
which means the generated script can be passed into a UNIX pipe to other
programs. This allows for some advanced use cases
and makes `genmvsteam.sh` much more powerful than it initially seems.

For more information and examples on how UNIX pipes work in general, see
[Pipeline (Unix) - Wikipedia](https://en.wikipedia.org/wiki/Pipeline_(Unix)).

Below are some examples of how pipes can be used with `genmvsteam.sh`.
Keep in mind that several of these examples can be combined as needed.

#### Writing the generated script to a file
Since `genmvsteam.sh` writes the generated script to standard output, 
we can simply redirect the output to a new file. Standard UNIX shell behavior.

Example:
```
./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Half-Life\ 2/ /run/media/deck/sdcard/steamapps/ > /tmp/movegame.sh
```

You can then view the generated script with any text editor or run it like so:
```
bash /tmp/movegame.sh
```

#### Copying games instead of moving
`genmvsteam.sh` creates a script that moves Steam games with `mv -nv` 
but there's no reason we can't _"find and replace"_ this command with another
that takes arguments the same way, such as `cp`
to copy the content instead of moving them.

Example:
```
./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Half-Life\ 2/ /run/media/deck/sdcard/steamapps/ | sed 's/mv -nv/cp -rnv/g'
```

To also write the generated script to a file,
redirect the output the same way as in the
[Writing the generated script to a file](#writing-the-generated-script-to-a-file)
example above:

```
./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Half-Life\ 2/ /run/media/deck/sdcard/steamapps/ | sed 's/mv -nv/cp -rnv/g' > /tmp/copygame.sh
```

#### Run the generated script immediately
It is possible to run the generated script immediately
without printing to the terminal or writing to a file by piping the
output straight into a shell interpreter like `bash`.

Example:
```
./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Half-Life\ 2/ /run/media/deck/sdcard/steamapps/ | bash
```

Since this skips any chance for you to inspect the generated script,
it should only be done when you are confident
the generated script will be correct.

#### Discovering and/or cleaning uninstalled or abandoned steamapps/common subdirectories
As part of the generated script `genmvsteam.sh` inserts comments
saying what folders the script will move
and puts the Steam app ID in parentheses.
Most common subdirectories only have one app ID, but some are home to multiple:
```
$ ./genmvsteam.sh ~/.local/share/Steam/steamapps/common/Portal/ ~/.local/share/Steam/steamapps/common/Half-Life\ 2 ~/.local/share/Steam/steamapps/
#!/bin/bash

# The following games will be moved to '~/.local/share/Steam/steamapps/common':
#       '~/.local/share/Steam/steamapps/common/Portal' (400)
#       '~/.local/share/Steam/steamapps/common/Half-Life 2' (220, 340, 380, 420)
...
```

`genmvsteam.sh` retrieves the app ID by looking at the `.acf` files
in the `steamapps` folder. Much like Steam client itself but in reverse. 
Since Steam reads the `.acf` files to understand what games are installed,
it cannot tell you about a `common` subdirectory not associated with any `.acf`
file which means that app ID appears to be uninstalled
from Steams perspective but still be using disk space.
When `genmvsteam.sh` searches the same `.acf` files for a `common` subdirectory
and can't find a match, it will still comment on the path it would move,
but there will be no number between the parentheses.

Example:
```
$ ./genmvsteam.sh /media/d/SteamLibrary/steamapps/common/NeosVR/ /media/d/SteamLibrary/steamapps
#!/bin/bash

# The following games will be moved to '/media/d/SteamLibrary/steamapps/common':
#       '/media/d/SteamLibrary/steamapps/common/NeosVR' ()
...
```
Knowing this, a wildcard can be used to find the app IDs of every common folder
while `grep` can be used to only print lines that contain `()` on them which 
show exactly which `common` subdirectories have no `.acf` file
associated with them.

Example:
```
$ ./genmvsteam.sh ~/.local/share/Steam/steamapps/common/* ~/.local/share/Steam/steamapps 2>/dev/null | grep "()"
#       '~/.local/share/Steam/steamapps/common/Crysis' ()
#       '~/.local/share/Steam/steamapps/common/NeosVR' ()
#       '~/.local/share/Steam/steamapps/common/The Stanley Parable Demo' ()
#       '~/.local/share/Steam/steamapps/common/Wolfenstein.The.New.Order' ()
```
